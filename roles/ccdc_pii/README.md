# ccdc_pii

Plants realistic-looking but **clearly fake (synthetic)** PII files on a Windows
10/11 desktop VM. The purpose is to give CCDC blue teams sensitive-looking target
data they must discover and protect (data-loss-prevention scenario). This is
standard defensive-competition target data.

> **All data generated by this role is synthetic test data.** Nothing in these
> files represents a real person, card, account, or credential. See
> "Why it is safe" below.

## What it plants

| File | Location | Contents |
|------|----------|----------|
| `customer_cards.csv` | `C:\CCDC-Data\` | `name,card_number,exp,cvv,type` — ~25 rows using only **public network TEST card numbers** (Visa `4111111111111111`, Mastercard `5555555555554444`, Amex `378282246310005`, Discover `6011111111111117`, etc.). Names/exp/CVV are randomized. |
| `bank_accounts.csv` | `C:\CCDC-Data\` | `name,routing,account,bank` — ~15 rows. Routing numbers all start `0000` (an invalid ABA prefix); accounts and bank names are fake. |
| `employees_pii.csv` | `C:\Users\Public\Documents\HR\` | `name,ssn,dob,address,salary,email` — ~20 rows. **SSNs use the 900–999 area range**, permanently reserved/invalid so they can never match a real SSN. Addresses use fake streets; emails use the reserved `.test` TLD. |
| `passwords.txt` | `C:\Users\Public\Desktop\Sensitive\` | Fake "IT password vault" — `system,username,password` — ~15 rows of weak passwords, simulating a poorly-secured secrets file. |
| `README_CONFIDENTIAL.txt` | `C:\Users\Public\Desktop\Sensitive\` | An in-character "confidential company data" note that adds realism as a competition target, plus an out-of-character staff note confirming the data is synthetic. |

Every generated file begins with the line:

```
SYNTHETIC TEST DATA - CCDC COMPETITION - NOT REAL
```

## Why it is safe (synthetic-data guarantees)

- **Credit cards** — only the publicly-documented test PANs published by the card
  networks/processors for QA. They pass Luhn but cannot be charged.
- **SSNs** — area numbers 900–999 are reserved by the SSA and are never issued,
  so no generated SSN can collide with a real one.
- **Emails** — use `.test`, an IETF-reserved non-routable TLD.
- **Bank routing numbers** — all prefixed `0000`, which is not a valid ABA range.

## Variables (`defaults/main.yml`)

| Variable | Default | Purpose |
|----------|---------|---------|
| `ccdc_pii_data_dir` | `C:\CCDC-Data` | Folder for the cards + bank CSVs |
| `ccdc_pii_desktop_dir` | `C:\Users\Public\Desktop\Sensitive` | Folder for password vault + confidential note |
| `ccdc_pii_hr_dir` | `C:\Users\Public\Documents\HR` | Folder for employee PII |
| `ccdc_pii_customer_cards_rows` | `25` | Rows in `customer_cards.csv` |
| `ccdc_pii_employees_rows` | `20` | Rows in `employees_pii.csv` |
| `ccdc_pii_passwords_rows` | `15` | Rows in `passwords.txt` |
| `ccdc_pii_bank_accounts_rows` | `15` | Rows in `bank_accounts.csv` |
| `ccdc_pii_header` | `SYNTHETIC TEST DATA - CCDC COMPETITION - NOT REAL` | First line stamped into every file |

The name/address/card/password pools are also in `defaults/main.yml` and can be
overridden. Randomized fields are seeded deterministically, so re-running the
role produces identical files (idempotent — `win_template`/`win_copy` only write
when content changes).

## Verify

After the role runs, on the Windows VM:

```powershell
Get-ChildItem C:\CCDC-Data, 'C:\Users\Public\Desktop\Sensitive', 'C:\Users\Public\Documents\HR'
Get-Content C:\CCDC-Data\customer_cards.csv -TotalCount 3
```

You should see the five planted files and the `SYNTHETIC TEST DATA ...` header on
the first line of each.
